# RiskLens AI

> Explainable AI-powered fraud risk analysis for modern payment systems.

RiskLens AI is a full-stack fraud risk analysis platform designed to help payment risk teams identify suspicious transactions, understand why a machine-learning model reached its decision, and determine an appropriate operational response.

The platform combines **predictive machine learning, SHAP explainability, deterministic risk intelligence, and Google Gemini** in an analyst-focused interface.

## What RiskLens AI Does

A traditional fraud model can return a prediction, but an analyst often needs more than a binary result.

RiskLens AI builds an intelligence layer around the fraud model.

For every transaction, the platform can provide:

- Fraud or Legitimate prediction
- Fraud probability
- Model confidence
- Operational risk level
- SHAP-based feature contributions
- Risk-increasing and risk-decreasing factors
- Analyst-oriented operational recommendation
- Gemini-generated investigation brief
- Deterministic fallback when generative AI is unavailable

The goal is not only to answer:

> **"Is this transaction suspicious?"**

but also:

> **"What model evidence contributed to the decision, and what should an analyst do next?"**

---

## Key Features

### Machine Learning Fraud Detection

A trained **Random Forest classifier** performs the underlying fraud prediction and produces the fraud probability used throughout the system.

### Explainable AI with SHAP

RiskLens AI uses **SHAP** to explain individual predictions and identify the features that most strongly influenced the model.

Each important factor is presented as either:

- `increases risk`
- `decreases risk`

along with its contribution strength.

### Risk Intelligence Layer

A deterministic risk-analysis layer converts model outputs into operational information such as:

- Low / Medium / High risk
- Manual Review Recommended
- Processing recommendations
- Analyst priority
- Recommended next action

### Generative AI Analyst

Google Gemini converts grounded model evidence into a concise investigation brief that is easier for an analyst to interpret.

Gemini receives only information already generated by the fraud-analysis pipeline.

It does **not** independently determine whether a transaction is fraudulent.

### Graceful AI Fallback

If Gemini is unavailable, misconfigured, or temporarily unreachable, the application automatically falls back to the deterministic risk analyst instead of breaking the prediction workflow.

### Analyst Dashboard

The React dashboard presents:

- Prediction
- Fraud probability
- Confidence
- Risk level
- Risk Analyst recommendation
- Generative AI investigation brief
- SHAP feature contributions
- Backend/model status

## AI Design

RiskLens AI deliberately separates **prediction**, **explanation**, **operational reasoning**, and **natural-language generation**.

### 1. Predictive AI

The Random Forest model is responsible for the actual fraud classification.

It produces:

```text
Fraud / Legitimate
Fraud Probability
Confidence
```

The language model does not make this decision.

### 2. Explainable AI

SHAP analyzes the model prediction and determines which features contributed most strongly to it.

Example:

```text
V14  -> increases risk
V17  -> increases risk
V10  -> increases risk
V4   -> increases risk
Time -> decreases risk
```

This allows the dashboard to show both supporting and counter-risk evidence.

### 3. Deterministic Risk Intelligence

The prediction and model evidence are converted into an operational assessment.

Example:

```text
Prediction:
Fraud

Fraud Probability:
57%

Risk Level:
Medium

Decision:
Manual Review Recommended

Recommended Action:
Hold the transaction for analyst review before approval.
```

### 4. Generative AI

Gemini receives grounded information such as:

```text
Prediction
Fraud Probability
Risk Level
Top SHAP Factors
Operational Decision
Recommended Action
```

It then converts this evidence into a concise payment-risk investigation brief.

The prompt explicitly prevents Gemini from inventing meanings for anonymized PCA features.

## Why the Generative AI Does Not Make the Fraud Decision

RiskLens AI intentionally uses the following architecture:

```text
Random Forest
      |
      | predicts
      v
SHAP
      |
      | explains
      v
Risk Engine
      |
      | recommends
      v
Gemini
      |
      | communicates
      v
Risk Analyst
```

This separation ensures that the generative model acts as an **analyst communication layer**, rather than an uncontrolled financial decision-maker.

---

## Model Explainability

The dataset contains anonymized PCA-transformed variables:

```text
V1, V2, V3, ... V28
```

RiskLens AI intentionally does **not** claim that these variables represent specific real-world concepts such as:

- customer location
- device type
- merchant category
- purchasing behavior

Such interpretations would not be supported by the dataset.

Instead, the application reports only what can be grounded in the model:

```text
Feature
SHAP impact
Direction of contribution
```

## Model Performance

The fraud model was developed using the Credit Card Fraud Detection dataset.

Dataset characteristics:

```text
Total transactions:      284,807
Legitimate transactions: 284,315
Fraudulent transactions:     492
Fraud rate:                ~0.17%
```

Baseline Random Forest evaluation:

```text
Fraud Precision: 0.93
Fraud Recall:    0.79
Fraud F1-score:  0.85
ROC-AUC:         ~0.96
```

Fraud detection is a highly imbalanced classification problem. For that reason, RiskLens AI focuses on metrics such as:

- Precision
- Recall
- F1-score
- ROC-AUC

rather than relying only on overall accuracy.

Create a Python virtual environment:

```bash
python -m venv venv
```


## Security Considerations

RiskLens AI follows several security and reliability principles:

- API keys are supplied through environment variables.
- Real secrets are excluded from Git.
- Gemini credentials remain on the backend.
- API keys are never exposed to the React client.
- The raw transaction dataset is excluded from the repository.
- Generative AI does not make the underlying fraud prediction.
- Gemini receives grounded model evidence rather than raw unrestricted context.
- SHAP explanations remain tied to actual model behavior.
- A deterministic fallback remains available if Gemini cannot be reached.
- CORS restricts browser access to configured frontend origins.
- The trained model artifact is included so the application can run without retraining.

## Dataset

RiskLens AI uses the Credit Card Fraud Detection dataset containing anonymized card transactions.

The raw dataset is intentionally excluded from the GitHub repository.

```text
creditcard.csv
```

inside:

```text
backend/data/
```

The trained model artifact is included in the repository so the deployed prediction service does not require the raw dataset at runtime.

## Reliability and Fallback Design

The core prediction pipeline does not depend on Gemini.

```text
Transaction
     |
     v
ML Prediction
     |
     v
SHAP Explanation
     |
     v
Deterministic Risk Analyst
     |
     +--------------------------+
     |                          |
 Gemini Available         Gemini Unavailable
     |                          |
     v                          v
AI Investigation          Deterministic
Brief                     Fallback
```

This means temporary generative-AI failures do not prevent the core fraud-analysis workflow from operating.
